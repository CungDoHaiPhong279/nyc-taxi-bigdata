## Payload and explicit parity-fixture exception

The payload is the unchanged 36-file Spark pipeline, nine frozen JSON metadata
files, the original artifact manifest, and the attributed public zone lookup.
The four tiny model Parquets contain two one-row categorical dictionaries,
616 learned tree-node rows and 20 tree-metadata rows. They are not trip tables.
Baseline metadata contains fitted group medians/counts, not individual labels.

**`artifacts/parity_inputs.json` is not synthetic:** it contains eight train
and eight validation feature-only records plus `parity_id`, preserved under
the user's explicit PACKAGE V2.2 resume exception. It has no fare labels,
journey keys, addresses, coordinates or exact pickup timestamps. The training
code derives these fixtures from each split's first eight retained rows. Frozen
parity-reference files hold corresponding model/baseline predictions. This
exception is not permission to distribute raw/sample datasets or August rows.

All 47 members retain their exact source bytes and hashes. Historical flags in
the frozen artifact manifest remain unchanged; they describe the artifact's
creation checkpoint, not the later deployment status. The outer local
`serving_manifest.json` (2,773 bytes of preparation bookkeeping) is omitted:
installer/startup artifact guards and inference use `artifacts/` plus `zones.csv`,
not that file. An existing legacy copy may be retained only at its separately
pinned hash; the installer never creates or rewrites it.

There are no raw/sample Parquets, per-trip fare labels, trip IDs, logs,
credentials, author-profile paths, MLflow database or runtime software in the ZIP.
`CONTENT_AUDIT.json` records the review categories without publishing fixture
values. This review is not a differential-privacy claim.
